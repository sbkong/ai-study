## 텐서 만들기

| 명령 | 설명 |
|---|---|
| `torch.tensor(data)` | 파이썬 리스트·numpy를 텐서로. 정수만 넣으면 `int64`가 된다 |
| `torch.zeros(*shape)` | 0으로 채운 텐서. 기본 `float32` |
| `torch.randn(*shape)` | 표준정규분포 난수. 평균 0, 표준편차 1 |
| `torch.arange(n)` | 0부터 n-1까지 연속 정수 |

## 꼬리표 읽기

| 명령 | 설명 |
|---|---|
| `.shape` | 모양. 막힐 때 제일 먼저 찍을 것 |
| `.dtype` | 숫자 하나의 저장 형식 (`float32`, `int64` …) |
| `.device` | 올라와 있는 메모리 (`cpu` / `cuda:0`) |
| `.ndim` | 차원 수 |
| `.numel()` | 전체 원소 개수 |
| `.element_size()` | 원소 하나의 바이트 수. `numel()`과 곱하면 메모리 용량 |

## 메모리 배치

| 명령 | 설명 |
|---|---|
| `.stride()` | 다음 칸으로 가려면 메모리를 몇 칸 건너뛰는지 |
| `.is_contiguous()` | 메모리 순서가 shape 순서와 일치하는가 |
| `.data_ptr()` | 메모리 시작 주소. 두 텐서가 같은 메모리인지 확인용 |
| `.contiguous()` | 어긋난 배치를 복사해서 정렬 |
| `.clone()` | 메모리를 공유하지 않는 독립 사본 |

## 모양 바꾸기

| 명령 | 설명 |
|---|---|
| `.view(*shape)` | 복사 없이 모양만 다시 봄. 연속이 아니면 실패 |
| `.reshape(*shape)` | 가능하면 view, 아니면 복사. 안전한 기본 선택 |
| `.t()` | 2차원 전치. 데이터는 안 움직이고 stride만 뒤집힘 |
| `.permute(*dims)` | 축 순서를 임의로 재배치. 3차원 이상에서 쓴다 |
| `.unsqueeze(dim)` | 지정 위치에 크기 1 차원 추가. 브로드캐스팅 축 맞출 때 |
| `.squeeze()` | 크기 1인 차원 제거 |
| `.expand(*shape)` | 복사 없이 늘려 보이게 함. stride가 `0`이 된다 |
| `.flatten()` | 뒤 차원들을 한 줄로 폄 |

## 타입 · device 이동

| 명령 | 설명 |
|---|---|
| `.float()` / `.long()` | `float32` / `int64`로 변환 |
| `.to(x)` | dtype 또는 device 변환. **복사이므로 대입해야 한다** |
| `.cpu()` | GPU 텐서를 CPU로 복사 |
| `torch.cuda.is_available()` | GPU를 쓸 수 있는가 |

## GPU 메모리 · 시간

| 명령 | 설명 |
|---|---|
| `torch.cuda.synchronize()` | GPU 작업이 끝날 때까지 대기. 시간 측정 전후에 필수 |
| `torch.cuda.memory_allocated()` | 텐서가 실제로 쓰는 VRAM |
| `torch.cuda.memory_reserved()` | PyTorch가 미리 확보한 VRAM. `nvidia-smi`에 보이는 쪽 |
| `torch.cuda.empty_cache()` | 참조 없는 캐시 VRAM 반납. `del` 뒤에 부른다 |
| `torch.cuda.get_device_properties(0)` | GPU 이름·총 VRAM 등 |

## 값 꺼내기 · 집계

| 명령 | 설명 |
|---|---|
| `.item()` | 원소 1개 텐서를 파이썬 숫자로. 로그 찍을 때 |
| `.mean()` | 평균. 정수 텐서에는 안 된다 |
| `.argmax(dim)` | 최댓값의 **위치**. 분류 예측에서 쓴다 |

# 부록 · 인자로 들어가는 숫자는 두 종류다

같은 모양의 숫자인데 함수마다 뜻이 다르다. 딱 두 종류로 나뉜다.

## 종류 ① 숫자 = 축의 **길이** (모양을 적는다)

"결과를 이런 모양으로 만들어라." 숫자 여러 개를 쓰면 그게 곧 shape다.

```python
torch.zeros(2, 3)        # 2행 3열 → shape (2, 3)
x.reshape(8, 784)        # 8행 784열로 만들어라
x.view(12)               # 길이 12인 1차원으로   ← 숫자 1개면 1차원
mean.view(3, 1, 1)       # 3 × 1 × 1 짜리 3차원으로
row.expand(1000, 1000)   # 1000 × 1000으로 보이게 늘려라
```

- `view(12)`의 `12`는 "12번째"가 아니라 **"길이 12"**
- 전체 원소 수는 반드시 맞아야 한다. `(3,4)`는 원소 12개니 `view(12)` `view(2,6)` `view(12,1)`은 되고 `view(5)`는 안 된다
- `-1`은 "남은 걸 알아서 계산해라". 한 자리에만 쓸 수 있다

```python
x = torch.randn(8, 1, 28, 28)   # 원소 6272개
x.reshape(8, -1)                # -1 자리는 6272/8 = 784로 자동 계산
```

**해당 함수:** `zeros` · `randn` · `reshape` · `view` · `expand`

## 종류 ② 숫자 = 축의 **번호** (위치를 가리킨다)

"몇 번째 축에 대해 작업하라." 길이가 아니라 좌석 번호다. 0부터, 왼쪽부터.

```
shape = (2,   3,   4)
축 번호  0    1    2
음수     -3   -2   -1     ← 뒤에서부터 세는 방식
```

`-1`은 항상 마지막 축이다. **종류 ①의 `-1`과 뜻이 완전히 다르다.**

```python
t = torch.randn(2, 3, 4)

t.argmax(dim=1)      # 1번 축(길이 3) 방향으로 최대를 찾아라 → 그 축이 사라져 (2, 4)
t.mean(dim=0)        # 0번 축(길이 2)을 평균으로 접어라       → (3, 4)
t.unsqueeze(1)       # 1번 자리에 크기 1 축을 끼워넣어라      → (2, 1, 3, 4)
t.permute(2, 1, 0)   # 새 0번은 옛 2번, 새 1번은 옛 1번, 새 2번은 옛 0번 → (4, 3, 2)
```

**해당 함수:** `argmax(dim=)` · `mean(dim=)` · `sum(dim=)` · `unsqueeze` · `squeeze` · `flatten(start_dim=)` · `permute`

## 나란히 놓고 보면

같은 `(2)`가 들어가도 결과가 이렇게 다르다.

```python
t = torch.randn(2, 3, 4)      # 원소 24개

t.reshape(24)        # 종류① → shape (24,)          "길이 24로 만들어라"
t.unsqueeze(2)       # 종류② → shape (2, 3, 1, 4)   "2번 자리에 축을 끼워라"
t.argmax(dim=2)      # 종류② → shape (2, 3)         "2번 축을 훑어 최대 위치"
```

## 구분하는 방법

| 단서 | 판정 |
|---|---|
| 인자 이름에 `dim`이 있다 | 종류 ② (dimension index) |
| 숫자가 여러 개 나온다 | 대체로 종류 ① (shape를 적는 것) |
| 인자가 하나뿐이다 | 대체로 종류 ② |

- `unsqueeze` / `squeeze`는 `dim=`을 생략해 쓰는 관례라 겉보기엔 안 보이지만 시그니처가 `(dim)`이다 → 종류 ②
- `permute`만 예외로 **축 번호를 여러 개** 받는다. 그래서 가장 헷갈린다

## permute 읽는 법

"새 순서를 옛 번호로 적는다"고 읽는다.

```python
img = torch.randn(2, 3, 32, 32)     # (N, C, H, W)
#                 0  1   2   3

img.permute(0, 2, 3, 1)             # → (2, 32, 32, 3) = (N, H, W, C)
#           ↑  ↑  ↑  ↑
#           N  H  W  C   ← 새 위치에 올 축의 "옛 번호"를 순서대로 적는다
```

0번 자리엔 옛 0번(N), 1번 자리엔 옛 2번(H), 2번 자리엔 옛 3번(W), 3번 자리엔 옛 1번(C).

## 함께 기억할 함정 두 개

**① `view`로 축을 바꾸면 에러 없이 값이 뒤섞인다.**

```python
t = torch.arange(24).reshape(2, 3, 4)
t.permute(2, 1, 0)   # (4,3,2) — 축을 바꾼다 (올바름)
t.view(4, 3, 2)      # (4,3,2) — 에러 안 남. 하지만 전치가 아니다
```

`view`는 메모리에 한 줄로 놓인 `0,1,...,23`을 **끊는 위치만** 바꾼다. 숫자 순서는 그대로다.

**② `reshape`은 원본과 연결됐는지가 상황에 따라 달라진다.**

연속 텐서면 view(메모리 공유), 아니면 복사(독립). 확인은 `.data_ptr()` 비교로.

```python
a = torch.zeros(2, 3)
a.view(6).data_ptr() == a.data_ptr()          # True  — 공유
a.t().reshape(6).data_ptr() == a.data_ptr()   # False — 복사됨
```
